# UI localisation plan (zh-Hans, zh-Hant, ja, es)

Written 2026-10-07 from an inspection of the code, and rebased onto `main` (after 0.2.1) the same day; the figures below are `main`'s. The owner approved all eleven decisions the same day; they are recorded as **L-1 to L-11** in `docs/decisions.md`, and this plan cites them. Progress is tracked in the stage table at the end.

## 1. Where things stood (verified 2026-10-07)

- **Stack.** Tauri 2, Svelte 5 (runes), TypeScript, Vite, Vitest, Playwright; macOS 13+ only. No i18n library.
- **Policy before L-1.** B10: every UI string lives in one English catalogue so the UI can be translated later; no translation or right-to-left UI in the MVP. P§17: the UI stays in the app's language and book content keeps its own direction. D4: extension `locales` is reserved, English only (`src-tauri/src/extensions/manifest.rs`).
- **The catalogue.** `src/lib/strings/en.ts`: about 380 entries, 76 of them functions, about 1,270 English words. Exported as the constant `t`, imported by 28 files. Plurals are English ternaries (`n === 1 ? …`, 8 in the catalogue and more outside it) and one “once / twice / n times”. Several strings compose English (`` `Highlight ${color.toLowerCase()}` ``).
- **English outside the catalogue.** `src/lib/extensions/labels.ts` (permission labels), `src/lib/commands/cheatsheet.ts`, colour names in `src/reader/annotations.svelte.ts`, `src/lib/library/when.ts` (“today”, “N days ago”, `en-GB`), menu names in `src/lib/commands/menu.ts` (also used as logic keys in `src/app/menubar.ts`), the Settings window title (`src/app/settingsWindow.ts`), the dialog filter and “Theme” chip in `src/prefs/ExtensionsPane.svelte`, and units, language names and an `en-GB` date in `src/app/BookInfo.svelte`.
- **Formatting.** `en-GB` hardcoded in `when.ts` and `BookInfo.svelte`; `NotesPanel.svelte` uses the system locale; library sorting uses `Intl.Collator(undefined)` (`src/lib/library/order.ts`).
- **Rust.** Import rejection reasons are English `thiserror` messages (`epub.rs`, `import.rs`) sent as `reason: String` and spliced into `t.import.rejected`.
- **Pages and windows.** `<html lang="en">` in `index.html` and `settings.html`. Two webviews (main, Settings), each importing the catalogue. Command titles are read at import (`CORE_COMMANDS`), the menu bar is built once. No `Info.plist`, so the bundle declares no localisations.
- **Settings.** Generic key/value `settings` table; `setting_set` takes any key; changes broadcast as `settings-changed`. `app_restart` (updater.rs) restarts through the N5 save path.
- **Fonts and layout.** UI font `system-ui`; six UI places use Literata, a Latin face. 52 fixed `width: Npx` rules; 41 `nowrap`/ellipsis/`letter-spacing`; 8 `text-transform: uppercase`.
- **Tests.** The in-app suite (`src/spikes/e2e.ts`) finds elements by English text (about 64 literals); visual baselines are English; every run starts with a fresh `LINEN_DATA_DIR`.
- **Not present.** No emails, server or telemetry (D1). Documentation is English.

## 2. Scope (L-1, L-10)

**In:** everything in Linen's own UI: the catalogue and the strings above, screen-reader text (aria labels, live announcements), menus, the Settings window, extension permission labels, import messages, date, number and plural formatting, and the page `lang`.

**Out:** book content and metadata (P§17), user notes, text supplied by extensions (D4), documentation, the crash log and Rust log text, the app name, Finder's “EPUB book” kind name (deferred), right-to-left UI (none of the four languages needs it). There are no emails.

## 3. Technical approach

**Catalogues.** Typed TypeScript, no library. `en.ts` stays the source; `Messages` is its shape with strings widened. Each language is `const ja: Messages = {…}`, so a missing or extra key, or a function with the wrong arguments, fails `pnpm check`. `src/lib/strings/index.ts` exports `t`, the resolved `locale` and the formatting helpers; features import `t` from there. All catalogues are bundled statically (no async load before first paint; §6.4).

**Locale identifiers.** `en`, `zh-Hans`, `zh-Hant`, `ja`, `es`: scripts for Chinese, no regions.

**Negotiation** (`negotiate.ts`, unit tested). For each preferred language in order: exact match; Chinese by script (`zh-TW`, `zh-HK`, `zh-MO` → `zh-Hant`; `zh`, `zh-CN`, `zh-SG` → `zh-Hans`; L-2); language (`es-*` → `es`; L-3); else the next one; finally `en`.

**Choosing and keeping the language (L-4, L-5).** The preferred languages come from the core (`NSLocale.preferredLanguages`), which follows the per-app language in System Settings. The Stage 0 spike showed that `navigator.languages` in WKWebView holds only the first language, so it is only the fallback (`docs/spikes/i18n-spike.md`). Settings › General › Language offers “System” (default) and each language in its own script (English, 简体中文, 繁體中文, 日本語, Español). It is saved as the `language` setting (`system` or a tag); an unknown value counts as `system`. Each page resolves its language before mounting and sets `<html lang>`. A change applies at restart: Settings offers Restart (`app_restart`, which saves first).

**Fallback.** Shipped languages are complete (type-checked). At run time a catalogue is merged over English, so a gap shows English, never a key; development builds log it and the test hooks count it.

**Rust errors.** `Rejection` and the import reasons are sent as `{ code, detail }` and mapped to `t.import.reasons[code]`; `Display` stays English for logs.

**Menus.** Menu names become ids with labels from `t.menus`; the `'Edit'`/`'Window'` checks compare ids. The bundle declares its languages in `Info.plist` (`CFBundleLocalizations`) so macOS lists Linen for per-app language and AppKit's own text follows; it lists only the languages that ship (spike finding 4). muda names the predefined items (Hide, Quit, Services, Cut, Copy, Paste…) in English itself, so each gets its `text` from the catalogue (spike finding 5).

**Pseudo-locale.** `en-XA` (accented, about 35 % longer, bracketed), in development builds only, to find overflow and strings that were missed.

## 4. Localisation details

- **Values in strings.** Functions, so translators may reorder. Quotation marks belong to each string: “…” en and zh-Hans, 「…」 zh-Hant and ja (L-11), «…» or “…” es. Colour sentences become whole sentences per language.
- **Plurals.** `plural(n, { one, other, many? })` over `Intl.PluralRules`. Chinese and Japanese have one form (translators add counters: 本, 冊, 件, 章). Spanish has `one`/`other` (`many` falls back to `other`).
- **Numbers.** `Intl.NumberFormat` for percentages (es “45 %”) and the number in a file size (es “1,5 MB”); the unit is a message (`info.sizeMB`), because Intl's English unit is “kB” and Linen's is “KB”. Western digits in all four languages. Counts are not grouped (“19959 results”), as before; grouping is left for later.
- **Dates.** The UI locale everywhere (no fixed `en-GB`, no `undefined`). Linen's English formats as `en-GB` (“7 Oct”, “21:40”), as the library always has; so the Notes tab, which followed the Mac's region, now shows English dates the British way too. Today/yesterday/N days ago via `Intl.RelativeTimeFormat` (`numeric: 'auto'`). Book languages named with `Intl.DisplayNames([locale])`. `Intl` cannot see the macOS 12/24-hour setting; the locale default applies.
- **Sorting (L-7).** `Intl.Collator(locale)`: pinyin in zh-Hans, strokes in zh-Hant, Japanese order in ja.
- **Fonts (L-8).** `<html lang>` must be exact (`zh-Hans`, `zh-Hant`, `ja`): Han characters share code points and `system-ui` picks PingFang SC/TC or Hiragino Sans by `lang`. UI text set in Literata uses the system Chinese or Japanese font in those languages; provisional until the design is approved. `:lang()` rules: `line-break: strict` for ja and zh, no added `letter-spacing`. Book text is unchanged.
- **Style (L-11).** Japanese です/ます; full-width punctuation in Chinese and Japanese. Spanish addresses the reader as *tú* (L-3).
- **Layout.** Spanish labels run longer (about 20–35 %, a rule of thumb, not measured here); Chinese and Japanese are shorter but need height. Watch: the Aa popover's segmented controls, Navigator tabs, the selection bar, the message bar, Settings rows, palette hints, the 52 fixed widths.
- **Keyboard.** Shortcuts match physical keys and labels follow the layout (T7); check single-key shortcuts with a Chinese or Japanese input method active.

## 6. Validation and rollout

- **Coverage.** The type check catches missing keys and wrong arguments. A Vitest check calls every function with marker values and asserts each appears (no dropped values), and reports strings identical to English against an allowlist.
- **Missed strings.** A scan of `.svelte` and `.ts` outside `strings/` for UI literals; an `en-XA` walk through the gallery and e2e captures.
- **Run-time gaps.** The test-hook counter is 0 at the end of an e2e run; `D1-no-uncaught-errors` stays last.
- **Switching and persistence.** Unit tests for setting → locale, unknown values and the preferred list. An e2e check seeds `language=ja` (spike builds) and asserts `<html lang>`, sample strings, menu labels and the restart notice. A real restart is checked by hand.
- **Layout.** The Playwright gallery in each language with axe; an overflow detector in e2e at the minimum window size; visual baselines stay English, per-language captures approved through `docs/visual/APPROVAL.md`.
- **Regressions.** The harness is pinned to `en`; `scripts/ci-local.sh --full`, the full e2e suite, `perf-coldstart.py` and `perf-memory.sh`; Rust tests for the error codes.
- **Translation review (L-6).** A native reviewer per language, in context, against the glossary; sign-offs in `docs/decisions.md`.
- **Rollout (L-9).** A minor release through `release.yml` and the updater, following the system language by default.
- **Rollback (L-9).** A reader switches to English in Settings; a patch release drops a language and its stored setting falls back to the system language, then English. No data migration.
